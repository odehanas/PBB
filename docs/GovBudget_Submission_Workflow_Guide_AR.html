١. المفاهيم الأساسية

  • كل طلب اعتماد مرتبط بـ: السنة + الجهة + الإدارة + الفئة. لكل فئة (REVENUE، HR، CAPEX، OPEX) مسار اعتماد مستقل وحالة مستقلة. اعتماد فئة المصروفات التشغيلية لا يؤثر على الفئة الرأسمالية وهكذا.
  • الإصدارات (Versions). يحتفظ كل مسار بأرقام إصدارات (Ver ١، ٢، ٣ …). يُنشأ إصدار جديد عند إعادة فتح العمل، ويُحفظ الإصدار السابق كسجل تاريخي (مرتبط بالإصدار الأصل) لإتاحة المقارنة.
  • القفل. لا يمكن إضافة أو تعديل أو حذف بنود الموازنة إلا عندما يكون الإصدار الأحدث بحالة Draft (مسودة). أي حالة أخرى تقفل إدخال البيانات.
  • سجل تراكمي. لا يستبدل النظام أي إصدار مُعتمَد أبداً. تؤدي إعادة الفتح دائماً إلى إنشاء مسودة جديدة (برقم إصدار تالٍ) مع الإبقاء على الإصدار السابق للتدقيق.

٢. دورة حياة الحالة (المسار الكامل)

Draft ──Submit──▶ Submitted ──Entity approve──▶ EntityApproved ──Send to central──▶ SentToCentral ──Sys approve──▶ SysApproved (final) ▲ │ │ │ │ │ Return/Unlock │ Return/Unlock (system admin) │ Return/Unlock (system admin) └──────────────────┴─────────────────────────┴──────────────────────────────────┘ (كل عملية إرجاع تنشئ مسودة جديدة = الإصدار التالي، مع حفظ القديم بحالة "Returned")
اتجاه الحركة ينتقل الطلب للأمام مرحلة واحدة في كل مرة. ولا يمكن إرجاعه للخلف إلا عبر الإرجاع / إلغاء القفل، وهو لا يعدّل النسخة المقفلة بل ينشئ مسودة جديدة قابلة للتحرير كإصدار تالٍ.

٥. الأدوار والصلاحيات — من يفعل ماذا

هناك ثلاثة أطراف. تتطلب شاشات الإدارة دور ADMIN أو SYSADMIN.

  • مستخدم الموازنة — يُدخل البنود ويُرسل، وبعد الإرجاع يبدأ التعديل. يعمل فقط ضمن سياقه المحدد (السنة / الجهة / الإدارة).
  • مسؤول مقيّد بجهة — ADMIN مرتبط بجهة واحدة. يتصرف فقط على طلبات جهته.
  • مسؤول على مستوى النظام — SYSADMIN، أو ADMIN دون تقييد بجهة. يتصرف عبر جميع الجهات وله صلاحيات إضافية (الاعتماد النهائي والإرجاع العميق).

٦. من يحق له إعادة فتح نسخة مُرسَلة للتعديل

هذا أكثر سؤال يتكرر. بمجرد أن يُرسل مستخدم الموازنة لا يعود قادراً على التعديل — تُقفل البيانات. وإعادة الفتح دائماً إجراء إداري اسمه الإرجاع (زر Unlock). وهو لا يعدّل النسخة المقفلة، بل ينشئ مسودة جديدة Draft كإصدار تالٍ، ثم يجري مستخدم الموازنة التصحيحات عليها.

القواعد

  • المسؤول المقيّد بجهة يمكنه الإرجاع فقط أثناء حالة Submitted — أي قبل أن يعتمده، ولجهته فقط.
  • مسؤول النظام يمكنه الإرجاع في مراحل لاحقة أيضاً: Submitted، EntityApproved، Approved (legacy)، SentToCentral.
  • لا يمكن إرجاع سوى أحدث إصدار في المسار.
  • يمكن أن يرافق الإرجاع ملاحظة إرجاع تشرح المطلوب تصحيحه، وتظهر للمستخدم.
SysApproved نهائي لا يوجد إرجاع/إلغاء قفل من حالة SysApproved. فبمجرد منح المالية المركزية الاعتماد النهائي، يُقفل هذا الإصدار ضمن الموازنة المجمَّعة الرسمية ولا يمكن إعادة فتحه عبر سير العمل.
ماذا يفعل «إلغاء القفل» فعلياً عند الضغط على Unlock في القائمة (أو Return في شاشة المراجعة): (١) يضع الإصدار الحالي بحالة Returned، (٢) ينشئ الإصدار التالي كمسودة Draft قابلة للتحرير ومرتبطة به، (٣) يسجّل طلب التعديل في سجل التدقيق. ثم يفتح المستخدم شاشة إدخال الموازنة ويضغط Start Revision عند اللزوم، فيحرّر ويعيد الإرسال.

٧. خطوة بخطوة — مستخدم الموازنة

  1. افتح إدخال الموازنة واختر تبويب الفئة (REVENUE / HR / CAPEX / OPEX).
  2. أضف البنود طالما الحالة Draft.
  3. اضغط Submit for Approval. تتحوّل الحالة إلى Submitted ويُقفل التعديل.
  4. إذا أرجعه المسؤول، ستظهر لافتة Returned مع الملاحظة. اضغط Start Revision لفتح المسودة الجديدة، صحّح البنود، ثم أعد الإرسال (يصبح هذا الإصدار التالي).

٨. خطوة بخطوة — المسؤول

  1. اذهب إلى طلبات اعتماد الموازنة واستخدم التبويبات للتصفية (مثلاً Submitted لإيجاد ما ينتظر المراجعة).
  2. اضغط Open لمراجعة إصدار. يمكنك مقارنته بالإصدار السابق لرؤية ما تغيّر بالضبط (انحراف لكل بند).
  3. اختر إجراءً:
    • Approve ← ينتقل إلى EntityApproved.
    • Return / Unlock ← يرجعه ويفتح مسودة جديدة قابلة للتحرير.
    • Send to central ← ينقل المعتمد من الجهة إلى SentToCentral.
    • Sys approve (مسؤول النظام فقط) ← اعتماد نهائي SysApproved.

٩. ماذا يحدث عند الاعتماد النهائي

عندما يمنح مسؤول النظام الاعتماد النهائي لطلب بحالة SentToCentral:

  • تتحوّل الحالة إلى SysApproved ويُختَم الإصدار كنهائي (من قام به ومتى).
  • تُكتب بنوده في مخزن الموازنة المجمَّعة النهائية الرسمية (مع استبدال أي أسطر سابقة لنفس الطلب)، وهو ما تقرأ منه التقارير والموازنة الموحَّدة.
  • الإصدار نهائي — لا يمكن إجراء أي تغييرات أخرى عليه.
