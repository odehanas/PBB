1. Key concepts

  • A submission is per Year + Entity + Department + Category. Each category (REVENUE, HR, CAPEX, OPEX) has its own submission stream and its own status. Approving OPEX does not affect CAPEX, etc.
  • Versions. Every submission stream keeps numbered versions (Ver 1, 2, 3 …). A new version is created when work is re-opened; the older version is preserved as history (linked by a parent reference) so you can compare changes.
  • Locking. Budget lines can only be added, edited or deleted while the latest version is in Draft. Any other status locks data entry.
  • Additive history. The system never overwrites an approved version. Re-opening always spawns a fresh Draft (next version number) and leaves the prior version intact for audit.

2. The status lifecycle (full flow)

Draft ──Submit──▶ Submitted ──Entity approve──▶ EntityApproved ──Send to central──▶ SentToCentral ──Sys approve──▶ SysApproved (final) ▲ │ │ │ │ │ Return/Unlock │ Return/Unlock (system admin) │ Return/Unlock (system admin) └──────────────────┴─────────────────────────┴──────────────────────────────────┘ (each Return creates a NEW Draft = next version; old version kept as "Returned")
Direction of travel A submission moves forward one stage at a time. It can be pushed backwards only by a Return / Unlock, which does not edit the locked version — it creates a brand-new editable Draft as the next version.

5. Roles & permissions — who can do what

There are three actors. Admin screens require the ADMIN or SYSADMIN role.

  • Budget user — enters lines, submits, and (after a return) starts the revision. Works only within their assigned Year / Entity / Department context.
  • Entity-scoped admin — an ADMIN tied to one entity. Can act only on submissions of their own entity.
  • System-level admin — a SYSADMIN, or an ADMIN with no entity restriction. Can act across all entities and has extra powers (final approval, deep return).

6. Who can re-open a submitted version for editing

This is the most-asked question. Once a budget user submits, they can no longer edit — the data is locked. Re-opening is always an administrator action called Return (the Unlock button). It never edits the locked version; it creates a fresh Draft as the next version, and the budget user then makes the corrections there.

The rules

  • Entity-scoped admin can return a submission only while it is Submitted — i.e. before they approve it, and only for their own entity.
  • System-level admin can return at later stages too: Submitted, EntityApproved, Approved (legacy) and SentToCentral.
  • Only the latest version of a stream can be returned.
  • A return can carry a return note explaining what to fix; the note is shown to the budget user.
SysApproved is final There is no Return / Unlock from SysApproved. Once central finance gives final approval, that version is locked into the official combined budget and cannot be re-opened through the workflow.
What "Unlock" really does Clicking Unlock on the list (or Return on the review screen): (1) marks the current version Returned, (2) creates the next version as an editable Draft linked to it, and (3) records the revision request in the audit trail. The budget user then opens Budget Entry, clicks Start Revision if needed, edits, and re-submits.

7. Step by step — budget user

  1. Open Budget Entry and choose the category tab (REVENUE / HR / CAPEX / OPEX).
  2. Add lines while the status is Draft.
  3. Click Submit for Approval. Status becomes Submitted and editing locks.
  4. If an admin returns it, you'll see a Returned banner with the note. Click Start Revision to open the new Draft, fix the lines, and submit again (this becomes the next version).

8. Step by step — administrator

  1. Go to Budget Submissions and use the tabs to filter (e.g. Submitted to find items awaiting review).
  2. Click Open to review a version. You can compare it against the previous version to see exactly what changed (variance by line).
  3. Choose an action:
    • Approve → moves to EntityApproved.
    • Return / Unlock → sends it back and opens a new editable Draft for corrections.
    • Send to central → moves an EntityApproved item to SentToCentral.
    • Sys approve (system admin only) → final SysApproved.

9. What final approval does

When a system administrator gives final approval to a SentToCentral submission:

  • Status becomes SysApproved and the version is stamped as finalized (who and when).
  • Its lines are written into the official combined final budget store (replacing any earlier rows for that same submission), which the reports and the consolidated budget read from.
  • The version is terminal — no further workflow changes are possible.

11. Quick reference & FAQ

QuestionAnswer
Can a user edit after submitting?No. Submitting locks the data. An admin must Return it first.
Who unlocks a submitted budget?Entity admin (while Submitted) or a system admin (at later stages too).
Does unlocking erase the submitted numbers?No. The submitted version is preserved as Returned; a new Draft version is created for edits.
Are categories approved together?No. Each category (REVENUE/HR/CAPEX/OPEX) flows and is approved independently.
Can SysApproved be re-opened?No. It is final and locked into the combined budget.
What is "Approved (legacy)"?An old status value equivalent to EntityApproved; behaves the same downstream.
How do I see what changed between versions?Open the version and use the version-compare (variance) view on the review screen.
